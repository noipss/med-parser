# План: парсер врачей УЗИ (Go + Tauri + React)

Единственный рабочий план проекта. Ход работ фиксируется в [STATUS.md](STATUS.md).

## 1. Цель и критерий приёмки
- Быстро собрать **только актуальных** врачей УЗИ по городу или области.
- Формат записи: `ФИО — Должность; сфера работы (специализации, место работы)`.
- Объём: 2000+ врачей, каждый врач — одна строка в БД.
- Стартовый стенд: запускается без ошибок, показывает работу и готов к доработке.

## 2. Источники (проверены по реальной разметке)
| Источник | Список УЗИ | Пагинация | Защита |
|---|---|---|---|
| napopravku.ru | `/{city}/doctors/vrach-uzd/` | `/page-N/`, 20 на странице | нет, достаточно HTTP |
| prodoctorov.ru | `/{city}/ultrazvukovoy-diagnost/` | `?page=N` | антибот + Яндекс SmartCaptcha (`r.prodoctorov.ru/unblock`) → нужен браузер |

Slug'и городов взяты из индекса Web Archive (≈150 для prodoctorov, ≈230 для napopravku).

## 3. Что считается «актуальным»
1. Данные загружаются в момент запуска: без кэша и без старых выгрузок. У каждой строки есть `checked_at`.
2. Врач сейчас ведёт приём: в карточке есть место работы (клиника) и запись или телефон.
   - prodoctorov: непустой `lpuIds` в `data-timetable-item` и/или список клиник.
   - napopravku: блок «Место приёма» (`workplace-address-card`) и кнопка «Записаться».
3. Отсеиваем карточки с маркерами «не принимает», «не ведёт приём», «больше не работает». Такие врачи учитываются в счётчике «отсеяно».
4. Экспорт берёт только врачей, **подтверждённых в текущей сессии**. Записи из прошлых сессий в документ не попадают.

## 4. Скорость
- Режим «Авто»: быстрый HTTP-пул (keep-alive, gzip, параллельно по хостам). Если источник блокирует, он автоматически переключается на браузер.
- Браузер: chromedp + системный Chrome, несколько вкладок параллельно. Картинки, шрифты и метрика блокируются. Профиль постоянный, поэтому решённая капча сохраняется.
- Капча: в видимом режиме парсер ждёт, пока оператор её решит. В фоновом режиме источник пропускается с сообщением в UI.
- Первая страница города сразу даёт число страниц, остальные качаются параллельно. Разбираются только списки, без захода в профили.

## 5. Хранилище (выбор)
- **SQLite** (один файл `uzi_doctors.db`, чистый Go без cgo): удобно передать заказчику, открывается в DB Browser, DBeaver или Excel через ODBC.
- **Excel (.xlsx)**: документ заказчику. Создаётся автоматически в конце сессии и по кнопке.
- Уникальность: `ФИО + город` (дубли из двух источников объединяются).

## 6. Архитектура
```
backend/  (Go)
  cmd/server        HTTP API :8765 + раздача UI
  internal/geo      регионы → города → slug'и (cities.txt, редактируемый)
  internal/fetch    HTTP-фетчер, браузерный фетчер (chromedp), детектор блокировок
  internal/sources  prodoctorov, napopravku: URL, разбор HTML, число страниц
  internal/engine   сессия: пул задач, дедупликация, фильтр актуальности, статистика
  internal/store    SQLite + экспорт XLSX
  internal/web      встроенная сборка UI (embed)
frontend/ (React + Vite + TS)  простой UI
src-tauri/ (Tauri v2)          окно приложения; Go-бэкенд как sidecar
scripts/                        dev / build
```
API: `GET /api/regions`, `POST /api/start`, `POST /api/stop`, `GET /api/status`, `POST /api/export`, `GET /api/export.xlsx`.

## 7. UI (минимальный)
Время сессии · Найдено врачей · Начать/Закончить · Город/область (с поиском). Дополнительно: отсеяно, страниц, скорость, режим (Авто/Браузер), «Показывать браузер», последние найденные, журнал, экспорт.

4. sources: парсеры + тесты на реальных HTML-снимках.
5. store: SQLite + XLSX.
6. engine: сессия, параллельность, актуальность, статистика.
7. API-сервер + встроенный UI.
8. Frontend React.
9. Tauri-оболочка + sidecar.
10. Скрипты сборки и запуска, README.
11. Проверка: `go test`, `go vet`, e2e на локальном стенде с фикстурами, сборка фронта, сборка Tauri, запуск.
